# Keys are looked up in Key Bindings, and two actions may share a key

Until 13g the Encounter Screen compared key codes itself: Space passed, Z undid, and Control held priority. 13g lets the player change them and adds a fourth, cancel (X), which does what the Info Panel's Cancel button does when that button is showing and nothing otherwise (A481, A488).

**One object says which key does what.** `KeyBindings` (`ui/key_bindings.gd`) holds a key for each of the four actions and answers two questions: what a press of a key does (`pressed_action`), and which key holds priority (`key_of`). The Encounter Screen asks it in `press_key()` and, each frame, for the Hold Key; nothing else in `ui/` compares a key code to an action. It belongs to `GameSettings`, which reads and writes one line for each action in `user://settings.cfg` by the key's name (`key_pass="Space"`). A line that is missing, or names no key, or names Escape, gives that action's default, as every other broken setting does. A screen with no settings path, as in a test, has the defaults and saves nothing.

**Any single key, for any action** (A480). A modifier can pass and an ordinary key can hold priority: the four actions are bound the same way and there is no rule about which kind of key suits which. A combination ("Ctrl+Z") cannot be bound, nor a mouse button; neither was wanted, and a combination would have to be told apart from the Hold Key going down. Escape is never bound: it opens and closes the Pause Menu, which is where a mistaken binding is put right.

**Two actions may share a key, and nothing is swapped** (A480). The first proposal swapped the two keys when one already in use was bound. The user chose to allow the clash and show it: the Controls Page draws every action that shares its key in red. So a shared key needs a rule, and it is this (A486): a press does only the first of pass, undo and cancel bound to it, in that order, since doing two (passing, then undoing the pass) is never wanted. Holding priority is a key held down and not a press, so it applies whenever its key is down, even a key that also passes. Every action always has a key; with clashes allowed there is nothing a binding would need clearing for (A487).

**The Controls Page is a page of the Pause Menu** (A485), reached from a Controls button on its settings page, with Back leading to the settings. It was asked for as a window of its own and built as a page: it reuses the menu's pages and nothing else on the screen can be clicked while the menu is open anyway. A row that is clicked waits for a key. While one waits, the screen hands the next key pressed to the menu before anything else looks at it, so the key is bound and does not also pass or undo; Escape then only stops the row waiting and leaves the menu open. No bound key acts while the Pause Menu is open, as before.

**Buttons name the key bound** (A481). The Pass Button reads "Pass Priority [SPACE]", the Undo button "Undo [Z]" and the Cancel button "Cancel [X]", each with whatever key does it now. The screen tells the three of them when a binding changes and at every redraw; each remembers the name, so one that is built again still shows it.
