# The Menu Backdrop is a still with its flicker, and the main menu's window is pinned to its parapet

The main menu stood on the plain slate (ADR 0035). It now stands on a picture of its own, the Menu Backdrop: Last Light, the top of a castle tower at nightfall, with the menu's window set into the tower's parapet as its middle merlon, the Menu Soldier standing on it, braziers on the corner merlons and open sky on either side for the Wisp. It was chosen from four variants in a prototype (branch `prototype/menu-backdrop`), and its loop was tuned there: the stars twinkle half as often as they first did.

**A Backdrop's size and look.** It is 320 × 180, drawn six screen pixels to each of its own with hard edges and never tiled, as the encounter's Backdrop is (ADR 0035), and its gradients are blended between neighboring tones with the same 4 × 4 Bayer ramp the encounter's placeholders use. It is never dimmed: nothing over it needs to read against it but the window, which is opaque, and the Wisp, which is brighter than anything in it.

**It is a still with its flicker, not a sheet of frames.** It plays a ten-second loop at ten frames a second in which only the braziers' flames and the light they throw, some of the stars and the light in an arrow slit change, each by a pixel or two: 317 of its 57,600 pixels. So it is kept as its still, the loop's first frame, and its flicker: each pixel that ever changes, one to a column, in its color on each frame, one to a row, with where each pixel is beside it (`last_light_flicker.json`). `MenuBackdrop` paints the frame's flicker onto a copy of the still and updates its texture as the frame changes. A sheet of the hundred whole frames, which the prototype played, was considered: simpler to play, but 23 MB of video memory for a picture that is almost all still. Drawing the flames, stars and slit in code was considered too, and would have written the art twice, once in the tool and once in the game.

**The tool is its source.** `tools/sprites/menu_backdrop.py` draws it, as `tier_medallions.py` draws the Tier Track's medallions, straight into `ui/sprites/backgrounds/menu/`, with a GIF of the loop in `tools/sprites/preview/`. Its tones are not in the shared palette, and its gradients and flicker are worked out, not drawn by hand. The still and the flicker are imported as Images, as pictures the code paints on are (the conventions' "Game-side code"). An Aseprite file the user could touch up was considered; the tool can learn to read one if hand edits are ever wanted.

**The window's top is pinned to the parapet.** The window and the Menu Soldier were centered on the screen together, so the window's top moved with the number of entries the menu holds: Continue, the developer entries, and the entries the finished menu will gain (milestone 35). The tower is fixed in the picture, so the window's top now lies on the picture's row 67, the merlons' tops (`MenuBackdrop.PARAPET`, 402 screen pixels down at 1080p), centered across the screen, and the soldier stands on it as before. The window's height still follows its entries: with few, as in a playtest build, the parapet's stone shows below it; with more than the developer menu's five, it reaches over the ledge below the parapet, and the picture or the window will need another look then. Fixing the window to the parapet's height whatever it holds was the alternative, and left empty space in a short menu. Drawing the tower to fit the window at run time was rejected as far more work for the same picture.

Only the main menu shows it. The menu's dialogs lie over it as they lay over the slate, and nothing else changes: the Wisp keeps off the window and above its bottom wherever the window is.
