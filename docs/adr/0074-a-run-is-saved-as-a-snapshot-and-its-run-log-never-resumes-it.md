# A run is saved as a snapshot, and its Run Log never resumes it

A saved run is a snapshot of the run's state, written on arriving at each Node, and Continue loads it. The Run Log is written beside it. With the Run Seed, the log replays the run exactly (ADR 0025), so it could have been the save itself: one source of truth, with the state rebuilt on Continue. That was rejected because a replay re-runs every decision the AI Agent made, its Monte Carlo rollouts included (ADR 0020), which could take minutes for a whole run. So the Run Log is kept for studying how runs are played and for replaying a playtester's bug, and nothing reads it to resume a run.

Amended at milestone 21's start: the Run Log holds the Villain's answers as well as the Hero's, so a replay feeds them back and never runs the AI, which keeps it fast and keeps it exact after the AI changes. The log still never resumes a run. Replaying a whole run still plays every encounter again, and a change to Content, such as a Rebalance, would send a replay down another road, where a snapshot simply takes the change.

**Saved runs and Run Logs carry their format and their build.** Each names its format version and the version of the build that wrote it. A build loads a saved run of its own format. One of an older format is refused with a notice, and the player starts a new run: there is no migration while the format still changes from one playtest build to the next. A change to Content, such as a Rebalance, simply applies to a loaded run. Every build shipped to playtesters is tagged in git, so a Run Log can be replayed against the build that wrote it.
