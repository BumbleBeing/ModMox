# The color of mana of any color is chosen in the Option Menu, a row for each color

Jewel Thief's Treasure, "{T}, Sacrifice this token: Add one mana of any color.", is the first mana ability whose mana's color is chosen. The engine offers it as one Action for each color, in WUBRG order, each with its `mana_type`, at priority and while paying, where every color is offered once any would pay something (engine ADR 0072). Until now `DecisionClicks` gave such a Treasure five rows that all read "{T}, Sacrifice this token: Add one mana of any color.". A throwaway prototype on a mock board built from the real pieces (`prototypes/choose_color/`) showed four ways to choose the color: A, the Option Menu, a row for each color where the Treasure was clicked; B, a Pip fan, the five mana symbols in an arc over the Treasure, one click choosing; C, the Info Panel, asking "Choose a color for Treasure" with a pip for each color in its Answer Row, selected there and given with the Pass Button; D, the Hero's five colored mana buttons glowing as the choices. Each was shown in two situations: at priority, and paying for Savannah Lions by hand with three Forests, none of which pays its {W}. The user chose "A, Option Menu", and the decisions below one at a time.

**Clicking the Treasure opens the Option Menu at the click, a row for each color**, at priority and while paying by hand alike. Each row is one of the engine's Actions, so a row answers with its index as every row does (ADR 0012, ADR 0022), and nothing new is asked: no window opens and no decision is added. A row is chosen with a click, and a click anywhere else closes the menu without making mana, as before.

**A color's row reads "Add {W}", "Add {U}", "Add {B}", "Add {R}" or "Add {G}"**, its symbol drawn as a pip. Pointing at it shows the ability in full in the Info Panel, as the menu does for the row under the cursor: "{T}, Sacrifice this token: Add {W}.", as `AbilityText.option_of()` words that color's activation. A `ClickOption` carries both: `row_text`, what its row reads, and `text`, what the Info Panel shows; for every other option they are the same, so every other row reads as it did.

**All five colors are in sight.** A menu shows as many rows as it has colors of mana of any color (`OptionMenu.most_rows_shown()`), so a Treasure's five show at once; every other menu still shows three and scrolls for the rest (A286). Turned down: three rows and a scroll, which hid two colors, and five rows for every menu.

**While the Hero pays by hand, a color that pays something still owed glows green**, the color of `DecisionClicks.Kind.PLAY`. Paying for Savannah Lions only "Add {W}" glows; with generic mana owed every color does. Whether a color pays is asked of the engine's own rule, `ManaPayment.symbol_paid_by()`, with what the `PayManaDecision` says is owed, so the Glow cannot disagree with where the mana goes. A color that pays nothing can still be chosen, and its mana goes to the pool (engine ADR 0072). At priority no row glows: every color can be chosen, so a Glow would say nothing, as in the Creature Type Window (ADR 0053). It is the first Glow on a row of the Option Menu, a `ClickOption`'s `has_glow`, drawn round the row as a Glow is round anything that is not a framed button; the menu cuts nothing off at its edge unless its rows scroll. Turned down: no Glow.

**Every row draws its mana symbols as pips**, written with a `SymbolLabel` as the Info Panel and the Pass Button are, not only a color's row. A row's words had been its button's text, so Temple Garden's rows read "{T}: Add {G}." with the braces showing. A row is still one line, cut off at its edge when it is too long, and the Info Panel shows it in full. Turned down: pips in the colors' rows only.

**Auto-tap asks nothing.** The payment planner picks the color as it picks any source (engine ADR 0072). The Tap Preview needs nothing new: it shows the payment of the row the cursor is on (ADR 0031), and a mana ability costs no mana, so a color's row previews nothing, as a land's row does. Turned down: asking the color while Auto-tap pays.

**No `ChooseColorDecision`.** Engine ADR 0072 records why one Action for each color was chosen over a decision asked as the mana is made: with it, the Option Menu's rows are those Actions.

**The cancel key closes an open Option Menu, and only that.** The words agreed for this said X closes the menu "as the Option Menu closes today", but it did not: at priority it did nothing while the menu was open, and while paying it canceled the whole cast, as the Info Panel's Cancel button does. Once that was found, the user chose that it closes the menu, any Option Menu and not only a color's, without choosing, as a click elsewhere does. While paying, the menu closes and the cast goes on; the next press cancels the cast. The innermost thing goes first, as Escape lets the Pinned card go before it opens the Pause Menu. Turned down: leaving it as it was.
