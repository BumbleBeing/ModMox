# Cards are added from Oracle Data and triaged against the engine's primitives

Every card in Content is a real Magic card, and adding one used to mean typing its characteristics by hand and writing a test that they were typed right. Cards are now added with `/add-card` (`.claude/skills/add-card/`), which runs the card tool in `tools/cards/`. Five choices about how it works are easy to undo by mistake, so they are written down here. The process around it (how many cards a session adds, where cards that are not added wait) is in the roadmap's card track.

**The tool writes what is mechanical, and a session writes the abilities.** The tool asks Scryfall for a card's Oracle Data and writes its printed characteristics from it with `ResourceSaver`: name, mana cost, card types, supertypes, subtypes, power and toughness, its first printing's Rarity, and the folder named for its first set. A vanilla creature is finished there. Abilities are composed from the engine's primitives in the session, by reading the Oracle text. A tool that read Oracle text and composed the abilities itself was rejected: it would be a parser for the whole of Magic's templating, and a wrong reading would make a card that looks right and plays wrong with nothing to notice it. Whatever the tool cannot read (an {X} or hybrid symbol, a card type the engine lacks, a "*" power, two faces) it names rather than guesses.

**Before any card is written, it is triaged.** Each card is Ready (the existing primitives give its exact Oracle behavior, no near misses), Blocked (it needs new primitives), Set Aside (it needs something new on screen, which starts with a GUI prototype) or Unsuited (it can mean nothing here, such as ante). Triage reads the primitives from the engine's own source each time, never from a hand-kept list that could fall behind it. A Blocked card's primitives are proposed and built test-first only after the user agrees, so a new primitive is a decision, never a side effect of adding a card. Nothing is written to Content for a card that is not being added, so a Blocked card never sits in the game missing an ability.

**A card's printed characteristics are held to its Oracle Data by one test.** The Oracle Data the tool fetched is kept in `content/cards/oracle.json`, keyed by card file name as the art manifest is, and one test checks every Card Definition's name, mana cost, types, supertypes, subtypes, power and toughness against it. This replaced writing a "has the right printed characteristics" test for each new batch, which nobody would keep up across hundreds of cards. A Rebalance (glossary) is a deliberate difference, written on the card's entry so the test lets that field through. Rarity is never checked, because Rarity is the field rebalanced most.

**The rules text is the check on the abilities.** Rules text is generated from abilities (ADR 0023), so text that reads as the Oracle text means the abilities were composed right. After a batch, each new card's generated text is reviewed beside its Oracle text, and a difference in meaning is a mistake fixed before the batch ends. That is why most cards get no behavior test: a card that repeats a tested pattern with other numbers, such as another "deals N damage to any target", is covered by the Oracle Data test, the review and its line in `test_ability_text.gd`. A card gets a behavior test when it puts primitives together in a way no test covers yet. The review is not a test, because ADR 0023 accepts wording that differs from Oracle's.

**Oracle text is read as if planeswalkers did not exist.** There will never be planeswalkers (ADR 0001), so a card is not held back, or made Unsuited, for mentioning them: its planeswalker words are dropped and the rest is composed as printed. "Target creature or planeswalker" is "target creature", "each creature and planeswalker" is "each creature", and "any target" already means a creature or a player. A card is Unsuited only when nothing is left once they are dropped, such as a Planeswalker card itself, or "destroy target planeswalker". Its rules text then reads without them, and the review accepts that as the same meaning. This is not a Rebalance: the Oracle Data test checks printed characteristics, which planeswalker words never touch, so nothing is written on the card's entry.
