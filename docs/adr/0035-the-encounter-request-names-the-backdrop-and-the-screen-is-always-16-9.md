# The Encounter Request names the Backdrop, and the screen is always 16:9

The glossary has said since Stages were designed that a Stage "sets the backdrop of its encounters". 13i draws one. No Stage exists in code, and ADR 0001 says not to build Stage or Tier data for the sake of a picture, so something else has to say which Backdrop an encounter has.

**The Encounter Request names it** (A498). `EncounterRequest.backdrop` is one of `Backdrops.NAMES`, set by `--backdrop=<name>` or the start form's choice, and refused by `validate()` when it is none of them. When runs exist, the Stage fills that field and nothing on the screen changes. Deriving the Backdrop from the Villain's deck was rejected: decks have two colors and a Stage has one, so the rule would have been invented now and thrown away.

**There are six, named for what a Stage is** (A499, A507): `plain`, which is the slate the screen always had and the default, and `white`, `blue`, `black`, `red` and `green`. A Stage is of one color, so one Backdrop for each color is all that can be told apart today. A Backdrop for each Tier waits for Tiers, and place names wait for Stages to have names.

**A Backdrop is one whole picture, 320 × 180, drawn six times over** (A504, A510, A511). It is pixel art like the Portraits, each of its pixels six screen pixels square at 1920 × 1080, and it is never tiled, so a detail can be painted anywhere and nothing repeats. `Backdrops.make()` returns what draws a Backdrop: the picture `<name>.png` in `ui/sprites/backgrounds/Encounters/` if there is one, with hard edges, and otherwise a placeholder drawn by a shader (`ui/backdrops/backdrop.gdshader`) on the same 320 × 180 grid, a landscape hint in that color (A497, A508). The user will replace the placeholders with their own art; putting a picture in the folder does it, with no change to code. A picture imports without mipmaps, as all pixel art does.

**The screen is always 16:9** (A505, A512 to A515). A picture of a fixed size needs a screen of a fixed shape. The project's stretch aspect is `keep`, where it was `expand`: the game is drawn at 1920 × 1080 and scaled, and a window or monitor of another shape gets black bars on two sides. Cropping, a focus point for each picture, and tiling were all considered for other shapes and none is needed. Snapping the window back to 16:9 after each resize was rejected: it flickers and does nothing for a fullscreen window on a 16:10 monitor. The window cannot be made smaller than 1280 × 720 (`MainMenu.MIN_WINDOW`, set by the main menu because the game always opens there), which is four times a Backdrop, so its pixels are even there as they are at 1080p (six), 1440p (eight) and 4K (twelve). In between they are slightly uneven, which was accepted.

`EncounterLayout` still works out every Region for wider and taller screens, and its tests still cover them (A514). That code is never reached now. It was left because removing it is a change across the whole Encounter Screen that 13i did not need.

**The Backdrop is built once, behind everything, and dimmed by the game** (A500, A506). `EncounterScreen.show_backdrop()` puts it just over the slate, the first child, and a dim layer just over it; neither is part of the board a snapshot redraws (ADR 0021), and both ignore the mouse. The dim layer is the slate's color at 55% (`Backdrops.DIM`), one strength for every Backdrop. Faces, Glows, block lines and pile labels were all tuned over the slate, and the prototype showed pile labels and empty piles nearly lost over an undimmed white or blue; at 55% everything read over white, the worst case. Dimming in code means a picture is painted at its own brightness and every one is darkened alike. Scrims under each player's rows were not needed. The plain Backdrop has no dim layer, so a screen without a Backdrop looks exactly as it did.

The Backdrop covers the whole screen. The sidebar keeps its opaque color over it and the middle band stays as it was (A500). It is still (A501): motion would need rules for Game Speed and the Pause Menu, and a shader or picture can gain it later. Only the Encounter Screen shows one (A502): the opening-hand overlay's scrim lets it show through dimly, and the main menu and start form keep the slate.

**Zone Plates set the zones off from the Backdrop.** After 13i landed the user asked for a rounded, mostly see-through gray rectangle behind every zone but the hands. A Zone Plate lies behind each of the four rows of the battlefield, at its Region, and behind each of the six piles, round its card and label; `EncounterLayout.zone_plates()` works out where, and one node (`ZonePlates`) draws them all, built once, over the dimmed Backdrop and under the board. They are drawn over the plain Backdrop too, so the plain screen no longer looks exactly as it did before 13i: it shows where each zone is.
