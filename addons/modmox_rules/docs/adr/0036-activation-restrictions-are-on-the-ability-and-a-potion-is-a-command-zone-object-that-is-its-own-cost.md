# Activation restrictions are on the ability, and a Potion is a command-zone object that is its own cost

Until milestone 14 an activated ability could be activated only from the battlefield, as often as its costs could be paid, whenever its controller had priority. Milestone 14 brings abilities activated from the command zone, two restrictions on activating, and Potions. It extends ADR 0011, which stands: an Emblem is still abilities and nothing else, is not a card, and cannot be targeted.

**An ability in the command zone is activated like one on the battlefield.** A player with priority is offered an `ActivateAbilityAction` for each activated ability of each command-zone object they control, under the same checks as a permanent's: its costs can be paid, its targets exist, its restrictions allow it. It is paid for, put on the stack and resolved by the same procedure (CR 113.6, 602.2). So an Emblem's ability can be responded to, and an effect that counters an ability, such as Stifle's, counters it (A518). One that could add mana and has no target is a mana ability and never uses the stack, as anywhere else: it is offered while a cost is being paid, counts toward whether a cost can be paid at all, and is marked Spent there too if it is once each game. `ManaPayment.sorted_sources_of()` is the one list of what a player may activate from, permanents and then command-zone objects, and `pays_while_paying()` the one check a mana ability passes in the middle of a payment; "only as a sorcery" never passes it, since something is on the stack.

**"Activate only once each game" and "activate only as a sorcery" are restrictions on the ability, not costs** (CR 602.5b, 602.5d; A518, A519). `ActivatedAbility` has a field for each. The first is checked against a mark the source's Game Object keeps for each of its abilities that has been activated, set when the ability is activated, so a countered ability is spent all the same. An Emblem never changes zones, so the mark lasts the game (ADR 0008); on a permanent it would last as long as the object does, which is what the rule means there too. Two Emblems with the same ability each keep their own. The second reuses the check a sorcery and a land play already pass: the controller's own main phase with an empty stack. A cost was the alternative for the first, a "spend this ability" beside `TapCost`; it was turned down because the rules call it a restriction, and because a cost is something a player pays and may be asked to choose. Only these two restrictions exist. "Once each turn" waits for a card that says it (ADR 0001).

**The Object View says which abilities are spent**, so the GUI can gray them and an Agent need not guess. It is public, like everything in the command zone.

**A Potion reaches the engine as an Emblem does, on a list of its own** (A521). A player's setup lists their Potions beside their Emblems: Card Definitions with abilities, a name and a rarity, and no mana cost. Each becomes a Game Object in the command zone at the start of the encounter. A Potion has one activated ability, and that ability's cost includes a new cost, "use up this Potion", which removes the Potion's object from the game. Using a Potion is therefore an ordinary `ActivateAbilityAction`, and what it does goes on the stack as an ability: Stifle counters it, Counterspell does not, and the Potion is gone either way because costs are paid first (A523). Casting it as a spell was the alternative; it would have needed a card for the Potion to be, a zone for it to be cast from and a place for it to go afterward, where the ability needs only the one new cost. A Potion that should be slow carries the sorcery restriction; one that does not can be used whenever its holder has priority.

**The engine knows a Potion from an Emblem only by which list it came from.** The Game Object remembers that, the Player View gives Potions on a list apart from Emblems (A522), both public, and the engine can say after the encounter which Potions each player used, so the game can delete those Items. An ability on the stack that came from a Potion carries that Potion's place in the list, since the Potion is gone by then and the GUI still shows which it was. No rule reads the difference. "Potion" is not a card type and neither is "Emblem": an Emblem still has no characteristics but its abilities (CR 114.4), and the type line the GUI shows for either is the GUI's own (A536).

**Undo and replay need nothing new.** The mark and the Potion's removal are part of the game state, so undoing an activation restores them under the usual rules (ADR 0015), and a replay of the Decision Log reaches the same state (ADR 0010).

**The Agent weighs a command-zone ability as it weighs a permanent's** (A527, ADR 0020). It has no rule for saving a once-a-game ability or a Potion for a better moment. One can be added if it is seen to waste them.
