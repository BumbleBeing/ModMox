# Layers are worked out for everything at once and kept until the next event

Continuous effects change characteristics in layers (CR 613): copy, control, text, type, color, abilities, then power and toughness in sublayers 7a (characteristic-defining abilities), 7b (setting) and 7c (modifying). Within a layer, effects apply in timestamp order. A layer is applied to every object before the next begins, and that is exactly how the engine works them out. For everything on the battlefield and in the command zone, the layer engine applies layer 6 to all objects, then 7a, 7b and 7c. While it runs, the characteristics query answers with the layers applied so far. A Filter used by a later layer, such as "creatures with flying get +1/+1", therefore sees what earlier layers did, and a filter asking about the characteristics being computed never recurses forever. Working out one object at a time was rejected for exactly that reason. CR 613.6 holds too: a static ability whose effect started applying in one layer keeps applying in later ones, even if a later effect in that layer removed the ability.

The result is kept until the next event is performed. Every change to the game is an event (ADR 0007), so throwing the result away in the event pipeline is always correct, and it is never copied with the state. This replaces ADR 0009's "recomputed on every query" for the battlefield and command zone, where the cache is needed for correctness as much as for speed. Objects in other zones still use their printed characteristics plus any characteristic-defining ability, which works in every zone (CR 604.3).

There are two sources of continuous effects. A static ability's effect applies to whatever matches right now (CR 611.3a), with its source's timestamp. A resolving spell or ability's effect, such as Giant Growth's "+3/+3 until end of turn", fixes what it affects and its numbers when it resolves (CR 611.2c, 608.2h), and is kept in the game state until its duration ends. The only duration so far is "until end of turn", which ends in the cleanup step together with damage removal (CR 514.2).

Timestamps need no counter of their own. Entering the battlefield always creates a new object with the next ID (ADR 0008), so an object's ID is its timestamp, and a created effect takes the next number from the same counter. Static abilities that only change rules rather than characteristics (keywords, extra land plays, blocking additional creatures) are asked about directly, but they still pass through layer 6, so an effect that grants or removes them works with no special handling.

Layers 1 to 5 and dependencies (CR 613.8) are not built yet; each is a named slot to fill when a card needs it. Auras will need more than object IDs as timestamps, because an Aura gets a new timestamp when it becomes attached without becoming a new object (CR 613.7e).
