# Layers are worked out for everything at once and kept until the next event

Continuous effects change characteristics in layers (CR 613): copy, control, text, type, color, abilities, then power and toughness in sublayers 7a (characteristic-defining abilities), 7b (setting) and 7c (modifying). Within a layer, effects apply in timestamp order. A layer is applied to every object before the next begins, and that is exactly how the engine works them out. For everything on the battlefield and in the command zone, the layer engine applies layer 4 to all objects, then layer 6, then 7a, 7b and 7c. While it runs, the characteristics query answers with the layers applied so far. A Filter used by a later layer, such as "creatures with flying get +1/+1", therefore sees what earlier layers did, and a filter asking about the characteristics being computed never recurses forever. Working out one object at a time was rejected for exactly that reason. CR 613.6 holds too: a static ability whose effect started applying in one layer keeps applying in later ones, even if a later effect in that layer removed the ability.

The result is kept until the next event is performed. Every change to the game is an event (ADR 0007), so throwing the result away in the event pipeline is always correct, and it is never copied with the state. This replaces ADR 0009's "recomputed on every query" for the battlefield and command zone, where the cache is needed for correctness as much as for speed. Objects in other zones still use their printed characteristics plus any characteristic-defining ability, which works in every zone (CR 604.3).

There are two sources of continuous effects. A static ability's effect applies to whatever matches right now (CR 611.3a), with its source's timestamp. A static ability may have a condition, "as long as this creature has three or more +1/+1 counters on it": it is asked as the ability's effects are about to apply in each layer, with the layers applied so far, as a Filter is, and an ability whose effect has already started applying in an earlier layer is not asked again (CR 613.6). A resolving spell or ability's effect, such as Giant Growth's "+3/+3 until end of turn", fixes what it affects and its numbers when it resolves (CR 611.2c, 608.2h), and is kept in the game state until its duration ends. The only duration so far is "until end of turn", which ends in the cleanup step together with damage removal (CR 514.2).

Timestamps need no counter of their own. Entering the battlefield always creates a new object with the next ID (ADR 0008), so an object's ID is its timestamp, and a created effect takes the next number from the same counter. Static abilities that only change rules rather than characteristics (keywords, extra land plays, blocking additional creatures) are asked about directly, but they still pass through layer 6, so an effect that grants or removes them works with no special handling.

Counters are the third thing that changes power and toughness. A +1/+1 or -1/-1 counter is kept on its permanent's Game Object as a number of each kind, not as a continuous effect, and the layer engine adds them in layer 7c after that layer's effects (CR 613.4c). Everything in 7c adds, so the order among effects and counters cannot change the result and a counter needs no timestamp. Putting and removing counters are events (ADR 0007), so the kept result is thrown away as for any other change, and a permanent that changes zones loses its counters by becoming a new object (ADR 0008).

Layer 4 adds subtypes ("is a Knight in addition to its other types", CR 205.1b), for Skyknight Squire. It also takes the creature type, and with it the creature types (CR 205.1b, 205.3d), from an Equipment with reconfigure while it is attached (CR 702.151b, ADR 0041). That comes from a rule of the keyword, not from a continuous effect, so the layer engine applies it to every such object before the layer's effects, as if its timestamp were the earliest; the timestamp it should have, from becoming attached (CR 613.7e), waits for a card whose type change could meet it. A land that has a basic land type has that type's mana ability (CR 305.6), and one that gains the type from an effect gains the ability with it (CR 305.7): after layer 4's effects, the layer engine gives every land the mana ability of each basic land type it has and lacks the ability of, so layer 6 sees it and can take it away, as "loses all abilities" does. A land's written abilities keep their places, the granted ones coming after them. Setting a land's subtype, which takes away the abilities of the types it loses (CR 305.7), waits for a card that does it. Layers 1 to 3 and 5, other type changes, and dependencies (CR 613.8) are not built yet; each is a named slot to fill when a card needs it. Auras will need more than object IDs as timestamps, because an Aura gets a new timestamp when it becomes attached without becoming a new object (CR 613.7e).

## Addendum: a rule-changing static ability may reach another object, and its condition is asked once every layer has applied

Bark of Doran's "As long as equipped creature's toughness is greater than its power, it assigns combat damage equal to its toughness rather than its power" changes a rule, the amount of combat damage a creature assigns (CR 510.1a), and it reaches another object, the creature the Equipment is on. It is an `AssignsCombatDamageByToughnessAbility` of the Equipment itself, with a Selection for what it reaches (`AttachedToSelection`) and an optional Condition. Combat damage assignment asks it, through `CombatProcedure.combat_damage_amount()`, as each creature's damage is assigned: the abilities of everything on the battlefield and in the command zone are read from the layers' result, and the Selection and the Condition are asked with that ability's controller and object, with every layer applied.

Granting the equipped creature an ability of its own in layer 6, under a `ContinuousStaticAbility`'s condition, was rejected for two reasons. That condition would be asked with the layers applied so far, before layer 7, so it would read power and toughness without Bark's own +0/+1 (layer 7c): a 2/2 that the Equipment makes 2/3 would not assign 3. And the rulings for Bark of Doran and Doran, the Siege Tower say the creature gains no ability and keeps its power: only the amount of combat damage it assigns changes, so a creature that loses all its abilities still assigns by toughness, and anything else that reads its power, such as a fight (CR 701.14a), reads it as ever. The AI's estimates of combat read the same amount (`CombatProcedure.combat_damage_amount()`), and the Combat Oracle and Rollouts run the engine's own combat, so they need nothing of their own.
