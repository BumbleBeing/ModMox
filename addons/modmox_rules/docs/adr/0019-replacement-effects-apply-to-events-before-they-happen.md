# Replacement and prevention effects change events before they are applied

A replacement or prevention effect (CR 614, 615) is a composable `MmReplacementEffect`. It answers two questions about an event that is about to be performed: does it apply, and what happens instead. Prevention is a kind of replacement effect in the code, though the glossary keeps both words because the rules do. What an effect applies to, and how much it has left, live in an `ActiveReplacementEffect` around it. There are two sources, as for continuous effects (ADR 0018). A static ability generates one while its source is on the battlefield, as protection does for "damage from black sources is prevented". A resolving spell or ability creates one with a duration, kept in the game state until the duration ends or it is used up, such as Fog's "prevent all combat damage this turn", a "prevent the next 1 damage" shield or a regeneration shield. "This turn" ends in cleanup together with "until end of turn" (CR 514.2), so they share one duration.

Every event goes through the replacement step in the event pipeline (ADR 0007). The step can turn one event into none, one or several, all in the same batch. Fully prevented damage becomes no damage at all, partly prevented damage becomes a smaller damage event, and a destruction replaced by regeneration becomes a tap, a removal from combat and the regeneration itself. Using up a shield is part of an event too (`DamagePreventedEvent`, `RegeneratedEvent`), so state still changes only through events. Prevented damage is never dealt (CR 615.1), so it triggers nothing and carries no deathtouch. It is recorded as a `DamagePreventedEvent` instead, for the GUI and for later "damage prevented this way" effects.

When several effects apply to one event, the affected player chooses which applies first (CR 616.1). That is the player being dealt damage, or the controller of the object being damaged or destroyed. The others are then checked again against the result, and each effect applies at most once to an event (CR 616.2). The choice is asked only when the order could matter. It is skipped when only one effect applies, when every effect would prevent all of the event without being used up, or when they are all interchangeable (the same content, the same amount left, locked to the same things). In those cases the earliest effect by timestamp applies. Self-replacement effects (CR 614.15) and the other ordering categories of CR 616.1 wait until a card has one.

Effects that change the rules rather than characteristics affect objects that arrive after they begin (CR 611.2c). A prevention effect is therefore locked only to the player or object its spell named, through a target, the controller or the source. Every other effect is matched by Filter when the event happens. A shield locked to a creature is lost when the creature changes zones, because the creature becomes a new object (ADR 0008).

A replacement choice can come up in the middle of a batch, and the engine never waits (ADR 0003). So a batch that needs a choice stops and is kept in the game state as a suspended batch, and the procedure that proposed it stops too. Answering the choice carries the batch on, and then the procedure. To make that possible, effects no longer perform events. Each effect proposes one simultaneous batch per step and works out its numbers once as it begins (CR 608.2h), and resolution walks the effects with a cursor. Combat damage and state-based actions carry on the same way. The suspended batch is copied, fingerprinted and checkpointed like the rest of the state, so undo works inside one (ADR 0015). Callers that nothing replaces yet, such as paying costs, playing a land or the draw step's draw, stay synchronous and assert that they never suspend. Each becomes resumable when a card first replaces its events.

Two alternatives were rejected. Working out every choice before performing, by asking the caller to collect them first, would need each caller to predict how replacement effects interact with one another and with the results of earlier events in the batch. Applying effects in timestamp order without asking is not what the rules say.

Protection (CR 702.16) is a keyword with a Filter for its quality, matched against the other object: the source of damage, a would-be blocker, or a spell, or the source of an ability, that would target it. Its damage prevention is an ordinary generated prevention effect, so it takes part in the ordering choice like any other. Indestructible (CR 702.12b) is a rule rather than a replacement effect: a destruction is never proposed, so a regeneration shield is not used up.
