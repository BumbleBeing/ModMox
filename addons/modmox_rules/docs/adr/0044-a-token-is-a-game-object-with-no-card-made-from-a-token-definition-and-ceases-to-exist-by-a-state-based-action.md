# A token is a Game Object with no card, made from a Token Definition, and ceases to exist by a state-based action

Tokens arrived with Prideful Parent, on the card track: "When this creature enters, create a 1/1 white Cat creature token." A token (CR 111) is a permanent that is not a card.

**A token is a Game Object whose Card Identity is `NO_CARD` and whose `is_token` is true.** Emblems and Potions already had no card; a token is the first object with no card that is a permanent. `is_token` is set by an event (`become_token()`), copied with the object, in the fingerprint and in the Object View, where it is public like the permanent. A token is never a Run Card, so nothing about a run (the Spoils, the deck) can see it, and `is_card()` is false for it as it is for an ability on the stack.

**A token is made from a Token Definition, an `MmCardDefinition` in its own file under `content/tokens/`.** The effect that creates it, `CreateTokenEffect` ("Create [amount] [token]", CR 111.2), names that file. A token's characteristics are set by the effect that makes it (CR 111.3), and a Card Definition already holds every one of them, so the characteristics query, the layers and the rules text treat a token like any other object. Its name is its subtypes plus "Token" (CR 111.4), written in the file. It is kept in its own file, not inside the card that makes it, so several cards can make the same token and the GUI can find its art by the file's name. The loaded definition is the token's `definition` and is never changed (ADR 0004), as an Emblem's is. The Object View carries it (`token_definition`) for that one use; the engine reads it only through the characteristics query (ADR 0009). So that the file survives into an encounter, flattening a Run Card (ADR 0004) now copies only the card's own parts, the sub-resources inside its file, and shares any resource that is a file of its own, as it was loaded; such a resource is read-only like the base Card Definition itself. Copying everything had given the token a nameless copy of its definition.

**A token's color comes from a color indicator.** Color was worked out from the mana cost alone (CR 202.2), and a token has none. `MmCardDefinition.color_indicator` (CR 204) lists colors the object has besides its mana cost's; printed characteristics are the union, in WUBRG order. A real card with a color indicator can use it too.

**Creating is one event per token, `TokenCreatedEvent`, all in one batch.** It makes the object under the creating player's control and ownership (CR 111.2), on the battlefield, untapped and summoning sick. It is not a `ZoneChangeEvent`, because nothing moves; but the token does enter the battlefield (CR 603.6a), so `ZoneChangeTrigger` matches it as an arrival from no zone: a trigger that takes any zone it came from sees it, and one that asks for a particular zone does not. The token's own "enters" abilities trigger the same way.

**A token that leaves the battlefield moves like a card and then ceases to exist.** A dying token goes to its owner's graveyard by an ordinary `ZoneChangeEvent`, which carries `is_token` to the new object, so "dies" and "leaves the battlefield" abilities see it (CR 111.7, 700.4). Then a state-based action removes every token that is anywhere but the battlefield, through `TokenCeasedEvent` (CR 704.5d); since state-based actions are checked before anyone has priority, no player ever sees a token in a graveyard, hand or exile. Making the zone change itself remove the token was rejected: "dies" triggers look back at the move (ADR 0017) and need it to be a real move to the graveyard.

**A token "that's attacking" enters attacking in the event that creates it.** Brimaz, King of Oreskos brought it: "Whenever Brimaz attacks, create a 1/1 white Cat Soldier creature token with vigilance that's attacking." `CreateTokenEffect.attacking` says so, and the effect sets `TokenCreatedEvent.attacking_on_arrival`, which records the new object among Combat's attackers as it puts it onto the battlefield (`MmCombat.enter_attacking()`), so nothing ever sees it there and not attacking (CR 508.4: "as it enters the battlefield"). It was never declared as an attacker: it isn't tapped (CR 508.1f), summoning sickness doesn't stop it, and attack triggers, which match the declaration (`AttackersDeclaredEvent`), never see it, since it is attacking but never "attacked". It attacks the defending player Combat already records: one on one, with no planeswalkers (game ADR 0040), that is all there is to attack, so CR 508.4 leaves no choice to ask. From then on it is an attacker like any other: it can be blocked, deals combat damage, is unblocked if it arrives after blockers are declared, and is removed from combat as any attacker is. The effect decides as it begins whether it may: only if attackers have been declared this combat and the token's controller is the active player; otherwise the token just enters (CR 506.3b; outside combat no one is attacking). A second event putting it into combat after it entered was rejected, as it would leave a moment where the token is on the battlefield and not attacking. So was keeping it apart from the declared attackers in Combat, until something asks whether a creature attacked (raid). Left out until a card needs it: a token put onto the battlefield attacking in the beginning of combat step, before attackers are declared, which CR 506.2 would have attacking; it just enters there.

**A token "that's blocking" a creature enters blocking it in the event that creates it.** Brimaz brought this too: "Whenever Brimaz blocks a creature, create a 1/1 white Cat Soldier creature token with vigilance that's blocking that creature." `CreateTokenEffect.blocking` is a Selection naming the creature it blocks, "that creature" here (`TriggeringObjectSelection`, the attacker Brimaz blocks), and the effect sets `TokenCreatedEvent.blocking_on_arrival` to that attacker's ID, so the event records the block as it puts the token onto the battlefield (`MmCombat.enter_blocking()`), with the same record a declared block makes. No `BlockersDeclaredEvent` is performed, so the token is blocking but never "blocked" (CR 509.7): block triggers, which match the declaration, never see it, and no block restriction is checked for it, since those apply as blockers are declared (CR 509.1b-c): it blocks a flyer it could not have been declared blocking. An attacker it blocks is blocked from then on, if it wasn't already (CR 509.1h). At combat damage it is one more of the attacker's blockers: there is no damage assignment order, so the attacker's controller divides its damage among all of them as for any attacker blocked by several (CR 510.1c), and the token deals its own as any blocker does. The effect decides as it begins whether it may: only under the control of the defending player (CR 506.3c), only blocking a creature that is still attacking (one that has left the battlefield or been removed from combat since it was named can't be blocked), and only once blockers have been declared; otherwise the token just enters. Left out until a card needs it: a token made blocking before blockers are declared, in the declare attackers step, which would otherwise be offered as a blocker again; it just enters there.

**"Nontoken" is a NotFilter of `IsTokenFilter`**, which reads `is_token` on the object or its last known information, so a token that has died is still seen as one (Arahbo, the First Fang: "another nontoken Cat you control").

**A token that's a copy is made from the copied object's definition.** Oltec Matterweaver brought it: "Whenever you cast a creature spell, choose one — • Create a 1/1 colorless Gnome artifact creature token. • Create a token that's a copy of target artifact token you control." `CreateTokenCopyEffect` ("Create a token that's a copy of [selection]", with an `amount`) proposes a `TokenCreatedEvent` for each object its Selection finds, made from `MmGameState.copiable_values_of()` that object: its definition, which is its copiable values (CR 707.2). For a token that is its Token Definition (CR 111.3); for a card, the card as its Run Card's Modifications made it (ADR 0004), which only a Mod aiming the effect at a card would reach. Counters, damage, the tapped state and continuous effects are not copied, and the copy is a new object like any created token, so it enters untapped and summoning sick and its own "enters" abilities trigger. The definition is shared, never changed (ADR 0004), so a copy of the copy has the same values and the GUI finds a copied token's art by its file as before. An object that has left the battlefield is copied as it last existed there (CR 608.2h). A copy of a permanent spell that becomes a token as it resolves is another thing (engine ADR 0083): it is not created (CR 608.3f, 111.13), so it makes no `TokenCreatedEvent`. `AbilityText` words it "create a token that's a copy of target artifact token you control", and "token" now follows a card type as Oracle words it ("artifact token", "creature tokens"), not before it.

Left out until a card needs it (ADR 0001): copy effects that change an object rather than making a token (CR 707.2), a copy with exceptions ("except it's a 1/1", CR 707.9), the art of a token copied from a card, predefined tokens other than Treasure (CR 111.10), a Token Definition with abilities in its rules text ("with flying"), and the number of tokens worked out by a Value. A predefined token is a Token Definition like any other: the Treasure came for Jewel Thief (ADR 0072), and only its words are its own, "create a Treasure token".

## Addendum: a token created attached, and the Role rule

Conceited Witch's Adventure, Price of Beauty, says "Create a Wicked Role token attached to target creature you control." The Wicked Role is a predefined token (CR 111.10): a colorless Enchantment — Aura Role with enchant creature, "Enchanted creature gets +1/+1." and "When this Aura is put into a graveyard, each opponent loses 1 life." It is Content, `content/tokens/wicked_role.tres`, named "Wicked Role" as the effect names it, not "Aura Role Token" (CR 111.4). Nothing new is drawn: an Aura token is drawn attached as any Aura is (game ADR 0042, 0045).

**"... attached to [selection]" is `CreateTokenEffect.attached_to`**, beside `attacking` and `blocking`. `TokenCreatedEvent.attached_to_on_arrival` attaches the token as it arrives, as `ZoneChangeEvent`'s does for an Aura spell (ADR 0064), so it is never on the battlefield unattached and no state-based action sees it so. One that could not legally be attached to what the Selection finds (`AttachmentRules.can_be_attached()`, its enchant ability and protection) is never created: an Aura with nothing it may legally enchant stays where it is (CR 303.4g), and a token being created has nowhere else to be. The event then retires the object it made and leaves `new_object_id` at 0, so nothing triggers on it. With nothing found, or more than one, the effect creates nothing at all. Creating the token and then attaching it with an `AttachEffect` was turned down: it would be on the battlefield unattached between the two, where "enters" abilities would see an Aura attached to nothing.

**The Role rule is a state-based action** (CR 303.7): when a permanent has more than one Role controlled by the same player attached to it, each but the newest is put into its owner's graveyard, with the reason `ROLE_RULE`, so a Wicked Role that is replaced still makes each opponent lose 1 life. Roles of different players, and other Auras, stay. An Aura that is attached illegally is left to CR 704.5m, so it is not counted twice. Game Objects keep no timestamp of their own (CR 613.7e), so the newest is the one with the highest ID. That is exact while the only way a Role is attached is by being created; a `Later` note in `StateBasedActions` says so. `AttachmentRules.ROLE` names the subtype.

`AbilityText` names a Role token by its name ("a Wicked Role token"), adds "attached to target creature you control", and has a Role call itself "this Aura", as any Aura does. A permanent that is no creature is "put into a graveyard from the battlefield" rather than "dies" (CR 700.4), as Oracle words it.

Scryfall prints Role tokens two to a flip card ("Wicked // Cursed"), each face named without "Role", so `TokenArt.part_for()` matches a Role by its face's name, and `TokenArt.tokens_made_by()` reads an Adventure's abilities too. A flip token's art crop on Scryfall is its whole upper face, rules text and all, so the art tool cuts it to the face's art panel (game ADR 0045's addendum).

The Agent needs nothing of its own: the simulation sees the +1/+1 and the life lost.

Left out until a card needs them (ADR 0001): the other Roles (Cursed, Monster, Royal, Sorcerer, Virtuous, Young Hero), a Role attached to a permanent that is no creature, and a timestamp for an object that becomes attached again.
