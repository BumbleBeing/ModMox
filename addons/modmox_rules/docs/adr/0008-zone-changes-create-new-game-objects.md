# A card that changes zones becomes a new Game Object

Following Comprehensive Rules 400.7, whenever a card changes zones it becomes a new Game Object with a new identity and no memory of its previous existence. Anything that refers to a Game Object refers to one specific identity, never to "the card", so "exile that creature at end of turn" correctly fails if the creature left and returned, and counters and attachments are lost. This is in place from the first milestone because making references identity-aware after the fact is notoriously painful. A new object starts untapped, with no counters on it. What an effect says it enters with, counters (CR 122.6) or tapped (CR 110.5b), is carried by the zone change itself and is true of the object as it arrives, so its "enters" abilities see it. So is a choice made as it enters, such as a creature type (ADR 0052), and like everything else it is forgotten when the permanent leaves. A permission Spent once each turn is Spent on its own object, so one that leaves and returns may be used again that turn (ADR 0054). The times an ability has resolved this turn are counted for its source object by ID, so one that leaves and returns starts again, while abilities it left on the stack still count for the object that left (ADR 0056).

What an object was like as it left is kept for the moments that ask about it afterward, its Last-Known Information (CR 608.2h). It was kept only for an object leaving the battlefield, for "dies" triggers and "its power". Lion Sash's "Exile target card from a graveyard. If it was a permanent card, put a +1/+1 counter on this permanent" asks about a card after it has left a graveyard, so a card leaving a graveyard is kept too, and a Filter or Value that reads `object_or_last_known()` finds it. A card leaving a hand or a library is not: what it was there is hidden from at least one player, and no card asks.
