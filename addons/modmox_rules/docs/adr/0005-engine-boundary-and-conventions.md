# The engine is a self-contained addon that knows nothing of the game

The rules engine lives in `addons/modmox_rules/` inside the game's repository, rather than a separate repo, but nothing in it references the game. It is built from `RefCounted` and `Resource` classes with no dependency on the scene tree, so it runs headless. Godot has one global `class_name` namespace shared with the game, so the prefix `Mm` is used, but only where a collision is plausible: the engine's core classes (`MmGameState`, `MmGameObject`, `MmPlayer`, `MmEncounterSetup`, `MmCardDefinition`, `MmRunCard`, `MmPendingDecision`) and the generic base classes (`MmEffect`, `MmFilter`, `MmValue`, `MmAbility`, `MmCost`). The specific pieces used to build cards carry no prefix and end with their kind (`DealDamageEffect`, `CreatureFilter`, `CountValue`, `ActivatedAbility`), keeping the Inspector readable while authoring.

The engine contains no game content. Authored Card Definitions, starting with the Alpha cards, live at `res://content/cards/`, and tests of that content live game-side at `res://tests/`. Engine tests build the cards they need in code.

Rules logic and card definitions refer to players only in relative terms (you, opponent, controller, owner) and never by Hero or Villain, which exist only for encounter setup and presentation. Otherwise a stolen permanent would benefit the wrong player.

GDScript in the engine is statically typed throughout, with untyped-declaration warnings treated as errors. Godot excludes `res://addons` from warnings by default, so the engine folder is explicitly re-included in `directory_rules`, and a test fails if that is ever undone. The setting is project-wide, so game code outside `addons/` is held to the same rule. Third-party addons such as GUT are not. Features are built test-first with GUT 9.7.1 (its Godot 4.7.x line), run headless.
