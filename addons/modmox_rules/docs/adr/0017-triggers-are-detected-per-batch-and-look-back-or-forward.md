# Triggers are detected right after each batch of events, looking back or forward

A triggered ability is found the moment its event happens, not later when someone would receive priority (CR 603.2). Right after an event, or a batch of simultaneous events, is applied and logged, the engine checks every working triggered ability against it and records each match as a pending trigger in the game state. The pending triggers go on the stack the next time a player would receive priority, after state-based actions (CR 603.3), in APNAP order with each player ordering their own. Scanning the event log only at that later point was rejected. It would check the game as it is then, so an observer that left the battlefield in between would wrongly miss its trigger, and a permanent that arrived in between would wrongly see an earlier event.

Events that happen at the same moment are performed together as one batch: state-based actions (CR 704.3), all combat damage in a step (CR 510.2), cleanup's damage removal, and an effect's damage to several recipients at once, as in "1 damage to each creature" (CR 120). Draws stay one per batch (CR 121.2). A batch can stop part-way for a replacement choice and carry on later (ADR 0019); triggers are still looked for once, after all of it. Each event in a batch carries the same batch number, and triggers are looked for once, after the whole batch. Leaves-the-battlefield triggers look back in time (CR 603.10a). They check everything that was on the battlefield just before the batch, including what left in it, so a creature that dies alongside others sees them die, and sees its own death. Every other trigger looks at the game after the batch, so permanents entering together see each other (CR 603.6a).

Looking back needs last-known information (CR 608.2h). When an object leaves the battlefield, its characteristics are frozen on it and the engine keeps it, so "that creature's power" and Filters still answer questions about it after it is gone. Every pending trigger records what triggered it ("that player", "that creature") and the Card Identity of its source, so the GUI can point at the card that caused an ability on the stack. An intervening "if" clause is checked both when the ability triggers and when it resolves (CR 603.4).

## Addendum: one event may trigger one ability several times

Brimaz, King of Oreskos, in the Villain deck `brimaz_king_of_oreskos`, says "Whenever Brimaz blocks a creature, create a 1/1 white Cat Soldier creature token with vigilance that's blocking that creature." Such an ability triggers once for each attacking creature its creature blocks (CR 509.3b), and a creature may block several (`BlockAdditionalAbility`, which an effect can grant), so one declaration of blockers may trigger it more than once, each time with another "that creature".

**`MmTrigger.triggering_object_ids()` lists the times an event triggers an ability**, each as the object that time is about ("that creature", 0 for none), and is empty when it does not trigger it. By default it is `matches()` with `triggering_object_id()`, so every other trigger is unchanged. `BlockersDeclaredTrigger` ("Whenever [filter] blocks a creature") gives the attacker of each block declared by a creature its Filter matches, by blocker ID and then attacker ID, whatever order the blocks were declared in. `TriggerDetection` records a pending trigger for each entry, and checks each one's intervening "if" on its own. A once-each-turn limit (ADR 0054's addendum) still lets the ability trigger only once: the first entry whose "if" holds is recorded, and the rest are already among the batch's.

Performing one event for each block instead was rejected. It would need nothing new here, but "Whenever this creature blocks" (CR 509.3a) triggers once however many creatures it blocks, and would then trigger for each, and the declaration every reader of the event log knows (the GUI, the AI, the tests) would become several events. Triggering at most once for each event was rejected too: it is enough while nothing lets a creature block twice, and wrong as soon as something does.

Left out until a card needs them (ADR 0001): "Whenever [a creature] blocks" (CR 509.3a), which would be a field on `BlockersDeclaredTrigger`, and "becomes blocked (by a creature)" (CR 509.3c-d).

## Addendum: several events of a batch may be one occasion (ADR 0082)

A trigger may say that some events of one batch are one occasion (`MmTrigger.occasion_of()`), and those trigger an ability once, for the first of them, as once each turn does. One lifelink source's damage to several recipients at once is one life gain (CR 119.9), so "Whenever you gain life" triggers once for it.
